§1 This in English Grammar

"This" is a demonstrative — it points. But what it points to depends on where it stands, who's speaking, and what came before. It is a deictic expression: its meaning is determined by context.

Deictic

👉 Pointing at something nearby

"This is my house." The speaker gestures or indicates proximity — physical, temporal, or discourse-near. "This" contrasts with "that" (proximal vs. distal). The closest English equivalent to a pointer in C.

Anaphoric

↩️ Referring back

"I saw a dog. This dog was huge." "This" reaches backward in the discourse to grab something already mentioned and hold it up for further comment. Like a backreference in regex.

Cataphoric

↪️ Referring forward

"This is what I think: we should leave." The pronoun appears before its referent. "This" promises content to come — a forward declaration. The speaker's equivalent of a function prototype.

Dummy

🎭 Dummy subject

"This is ridiculous." There's no specific thing being pointed at — "this" fills the subject position so the sentence can stand. It's syntactic scaffolding. It's undefined that happens to be grammatically required.

Discourse marker

💬 Conversation management

"So, this happened." In spoken English, "this" often marks a new topic, a story opener, or a shift in conversation. It's less a pronoun and more a stage direction: "now entering: something new."

Filler

🫥 The placeholder

"I was like, this close to winning." Sometimes "this" barely means anything — it hovers between adverb and gesture, doing the work of a word while being a shrug. It's the JavaScript undefined of natural language.

"This is the most overworked word in the language. It's a pronoun, an adjective, an adverb, a discourse marker, and sometimes barely a word at all." — every linguist, exhausted

§2 This in Programming

Every major language has a this or self — and every one of them gets it wrong differently. The binding rules are the language's theory of context, and the bugs are where the theory meets reality.

JavaScript

🟡 JavaScript — the chaos one

In JS, this is dynamically bound. Its value depends on how the function was called, not where it was defined. Arrow functions inherit it lexically. Regular functions rebind it. .bind(), .call(), and .apply() can override it. In strict mode it's undefined instead of the global object. Nobody fully understands it. We all just use arrow functions now.

javascript const obj = { name: 'Alice', greet() { return this.name }, arrow: () => this.name } obj.greet() // → 'Alice' const g = obj.greet; g() // → undefined (strict) obj.greet.call({name:'Bob'}) // → 'Bob' 🔄
Python

🐍 Python — the explicit one

Python doesn't have this. It has self, and you have to type it. Every. Single. Time. It's the first parameter of every method. It's not a keyword — it's a convention. You could call it potato and Python wouldn't care.

python class Cat: def __init__(self, name): self.name = name def greet(self): return f"I am {self}.name}" # self is NOT a keyword. this works: class Dog: def bark(potato): return 'woof' # 🥔
Java

☕ Java — the reliable one

In Java, this is lexically bound to the current instance. Always. No surprises, no dynamic rebinding. It just works. Boring, beautiful, predictable.

java class Person { String name; Person(String name) { this.name = name; } void introduce() { System.out.println("I am " + this.name); } }
C++

⚙️ C++ — the pointer one

In C++, this is a pointer, not a reference. You write this->member. It can be nullptr if you do something terrible. In const methods, this becomes const.

cpp struct Widget { int value; void set(int v) { this->value = v; } int get() const { return this->value; } Widget& chain() { return *this; } };
Rust

🦀 Rust — the &self one

Rust doesn't use this. It uses &self, &mut self, or self. The reference type encodes borrowing rules directly into the signature.

rust impl Counter { fn get(&self) -> i32 { self.value } fn inc(&mut self) { self.value += 1; } fn consume(self) -> i32 { self.value } }
Go

🐹 Go — the receiver one

Go has no this and no self. Methods are functions with a receiver, and you name it whatever you want. Convention says use a short abbreviation.

go func (s Server) Port() int { return s.port } func (s *Server) SetPort(p int) { s.port = p }
C#

🔷 C# — the extension one

C# has this like Java, plus extension methods via this as a modifier, and indexers via this[]. One keyword, three jobs.

csharp public int this[int i] { get => items[i]; } static void Shout(this string s) => Console.Write(s.ToUpper());
Ruby

💎 Ruby — the implicit one

In Ruby, self is implicit. You don't write self.method — you just write method. self appears only for disambiguation or class methods. It's always there even when you don't see it.

ruby class User def name; @name; end # implicit self def self.create(name); new(name); end end
PHP

🐘 PHP — the dollar one

PHP uses $this — with the dollar sign. It's a special variable, the only one that can't be reassigned. self:: refers to the class, static:: does late static binding. Three words for "this."

php class Logger { function log($msg) { echo $this->level . $msg; } }
Swift

🦅 Swift — the optional one

Swift uses self as a keyword, not a convention. You mostly don't need it. Closures capture self explicitly with a capture list. In escaping closures, self. is required. Unless you use [weak self]. Then it's optional. Then it might be nil.

swift let closure = { [self] in print(self.title) }
Kotlin

🟣 Kotlin — the it one

Kotlin has this for the current receiver, but also it — the implicit name for a single-parameter lambda. it is what this wishes it could be: invisible, effortless, always there.

kotlin list.map { it * 2 } // it = each element
TypeScript

🔷 TypeScript — the typed chaos

TypeScript inherits all of JavaScript's this chaos, then tries to type it. You can declare this: Type as a phantom parameter — visible to the type checker, invisible at runtime.

typescript function handleClick(this: Btn, e: Event) { console.log(this.label) // typed! }

§4 The Scope of This

In both English and programming, "this" has scope. Its reference shifts depending on where you are in the sentence, the conversation, or the call stack.

English Scope

// Conversation scope [Speaker A] "I bought this old typewriter." [Speaker B] "Oh nice, that's cool." ↑ "that" because it's A's thing, not B's [Speaker A] "But this key is stuck." ↑ "this" — narrowing scope to a part [Time passes. New conversation.] [Speaker A] "Remember that typewriter?" ↑ "that" now — it's distant in time // Scope shifted: spatial → temporal. Same object, different deictic.

JavaScript Scope Tree

globalThis → window / global / undefined (strict) // the root of all confusion
obj.method() → this = obj // the normal case
obj.method() → inner() → this = undefined ⚠️ // lost binding
obj.method() → () => this → this = obj ✅ // arrow inherits
obj.arrow = () => this → this = globalThis ⚠️⚠️ // arrow at object level = lexical global
new Thing() → this = fresh object ✅ // constructor binding
.call({}) / .bind({}) → this = whatever you pass // explicit override
